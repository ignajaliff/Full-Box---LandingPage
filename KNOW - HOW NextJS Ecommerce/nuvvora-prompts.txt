## 1. INICIO DE PROYECTO

Usar una sola vez al arrancar.

```
Vamos a desarrollar un ecommerce a medida para [NOMBRE DEL CLIENTE].

Antes de escribir cualquier código, lee y respeta estrictamente estos documentos:
@CLAUDE.md
@ai-pmp/rules.txt
@ai-pmp/frontend-rules.txt
@ai-pmp/supabase-rules.txt
@ai-pmp/ecommerce-rules.txt
@ai-pmp/error-handling.txt
@ai-pmp/naming-rules.txt

Tu única tarea en esta sesión:
1. Crear el proyecto Next.js 16 (App Router, TypeScript strict, Turbopack) con la
   estructura de carpetas de rules.txt (app/ con grupos (shop) y (admin), features/,
   shared/, lib/, data/, integrations/)
2. Configurar Tailwind v4 + shadcn/ui y el QueryClient provider (Client) en el layout
3. Crear los tres clientes de Supabase (browser, server, proxy) según supabase-rules.txt
   y el proxy.ts de refresco de sesión
4. Crear la página de login (/auth/login) con email y contraseña usando shadcn/ui y
   React Hook Form + Zod
5. Crear el helper del DAL requireRol() y un layout (admin) protegido

Restricciones:
- NO conectar todavía la auth con Supabase real (solo el andamiaje)
- NO crear módulos de catálogo ni checkout
- NO instalar dependencias fuera del stack de rules.txt
- Al terminar, listar exactamente qué archivos creaste
```

## 5. MÓDULO CHECKOUT + MERCADO PAGO

```
Vamos a desarrollar el checkout con Mercado Pago.

Antes de empezar respeta:
@CLAUDE.md
@ai-pmp/rules.txt
@ai-pmp/ecommerce-rules.txt
@ai-pmp/payments-rules.txt
@ai-pmp/supabase-rules.txt
@ai-pmp/error-handling.txt
@ai-pmp/naming-rules.txt

Backend:
- Tabla "ordenes": numero_orden (GENERATED ALWAYS AS IDENTITY), user_id, estado
  (check pendiente/pagada/enviada/cancelada), total (numeric(12,2)), metodo_pago,
  pago_id
- Tabla "items_orden": orden_id (FK), producto_id (FK), cantidad (check > 0),
  precio_unitario (numeric(12,2)) congelado
- Función SQL atómica para descontar stock (UPDATE ... WHERE stock >= cantidad)

Flujo (todo en el server, según payments-rules.txt):
1. Server Action recibe solo [{producto_id, cantidad}], lee precios/stock de la base,
   valida stock, calcula el total en el server, crea la orden pendiente + items_orden
2. Crea la preferencia de Mercado Pago con external_reference = orden.id y devuelve init_point
3. Route Handler /api/webhooks/mercadopago: valida x-signature (HMAC-SHA256,
   timingSafeEqual), re-consulta el pago a la API, procesa el estado de forma idempotente,
   descuenta stock solo en approved
4. Páginas /checkout/exito|error|pendiente (solo UX, no marcan pagada)

Restricciones:
- El total y el stock se manejan SOLO en el server
- Access token y webhook secret SIN prefijo NEXT_PUBLIC_
- La back_url NUNCA marca la orden como pagada
- RLS: el cliente ve solo sus órdenes; las transiciones de estado van por service key
- Al terminar, correr get_advisors del MCP y corregir alertas
- Al terminar, listar qué archivos creaste o modificaste
```
